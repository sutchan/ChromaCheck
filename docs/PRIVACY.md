## 1. 隐私设计原则

色辨 ChromaCheck 以**隐私优先**为第一设计原则：

1. **数据最小化**：仅收集提供服务所必需的最少数据。
2. **本地优先**：核心检测数据默认仅存储在用户本地浏览器，不上传服务器。
3. **用户掌控**：用户可以随时查看、导出、删除自己的数据。
4. **默认匿名**：不强制注册登录，不收集个人身份信息。
5. **透明告知**：所有数据收集行为均明确告知用户。

## 2. 数据收集范围

### 2.1 本地存储的数据（默认）

以下数据仅存储在用户本地浏览器（localStorage），**不上传服务器**：

| 数据 | 说明 | 保存时长 |
|------|------|----------|
| 检测结果 | 答题记录、判读结果 | 用户主动删除或自动清理（最多 20 条历史 / 5 条完整结果） |
| 检测进度 | 进行中的测试进度 | 测试完成后自动清除 |
| 用户设置 | 音效、主题、自动下一题等 | 直到用户修改 |

### 2.2 可选的匿名统计数据（需用户同意）

> **v1.0 实际**：应用完全本地运行，**无任何数据上报**（无 `analyticsEnabled`、无网络请求）。以下为 v1.1 规划的匿名上报字段（开启后仅上报脱敏数据）：

| 数据 | 说明 | 是否含身份信息 |
|------|------|----------------|
| 事件类型 | test_start / test_complete 等 | 否 |
| 测试类型 | quick / standard / advanced（v1.3） | 否 |
| 测试时长 | 毫秒数 | 否 |
| 结果摘要 | normal / suspected_* | 否 |
| 事件时间 | ISO 时间戳 | 否 |

**不上报的数据**：
- IP 地址
- 设备信息 / User-Agent
- 浏览器指纹
- Cookie / 广告标识符
- 用户姓名、邮箱、手机号
- 详细答题记录

### 2.3 不收集的数据

- 个人身份信息（姓名、身份证号、手机号等）
- 位置信息
- 通讯录 / 照片 / 文件
- 第三方网站行为

## 3. 数据存储与安全

### 3.1 存储位置

| 数据类型 | 存储位置 |
|----------|----------|
| 检测结果 | 用户浏览器 localStorage |
| 匿名统计（可选） | 服务端（仅聚合统计，30 天后清理明细） |
| 应用代码 / 检测图 | 服务端 CDN |

### 3.2 传输安全

- 全站强制 HTTPS（TLS 1.2+）。
- 检测结果仅在用户本地处理，不经过网络传输（本地优先架构）。
- 匿名上报使用 HTTPS + 幂等事件 ID 防止重复。

### 3.3 访问控制

- 本地数据：仅用户本人浏览器可访问，其他网站无法读取（浏览器同源策略）。
- 服务端统计：仅项目管理员可访问，数据只用于产品优化。

### 3.4 数据删除

用户可通过以下方式删除数据：
- 历史记录页：删除单条 / 清空全部。
- 浏览器设置：清除网站数据（localStorage）。
- 数据删除后不可恢复，服务端不留存备份。

## 4. 医学合规要求

### 4.1 产品定位

本产品为**色觉筛查工具**，不是医疗器械，不做医学诊断。

### 4.2 措辞规范

| 禁止使用 | 允许使用 |
|----------|----------|
| 确诊 / 诊断 / 判定患病 | 疑似 / 提示 / 建议就医 |
| 您是色盲 | 检测结果提示可能存在色觉异常 |
| 治愈 / 治疗 | 就医咨询 / 进一步检查 |

### 4.3 免责声明展示位置

- 首页页脚
- 检测前指引页
- 结果页
- 报告导出内容

### 4.4 合规建议

- 上线前咨询医疗法律顾问。
- 结果页明确提示"不能替代专业医学诊断"。
- 建议异常用户前往正规医院眼科检查。
- 不涉及处方药、治疗方案等医疗行为。

## 5. 法律法规合规

### 5.1 中国法律法规

| 法规 | 合规要点 |
|------|----------|
| 《个人信息保护法》(PIPL) | 最小必要原则、用户同意、数据主体权利 |
| 《数据安全法》 | 数据分类分级、安全保护义务 |
| 《网络安全法》 | 网络安全保护、个人信息保护义务 |
| 《未成年人保护法》 | 未成年人信息保护（儿童模式单独处理） |

### 5.2 未成年人保护

- 如面向未成年人提供服务：
  - 14 岁以下需监护人同意。
  - 不收集未成年人个人信息。
  - 提供儿童模式时，界面和内容需适龄。
  - 不展示广告或诱导分享。

### 5.3 国际合规（远期）

- 如服务海外用户：遵循 GDPR、CCPA 等。
- 提供数据导出（可携带权）、删除（被遗忘权）。

## 6. 隐私政策要点（面向用户）

以下内容应发布为公开的隐私政策页面：

1. **我们收集什么**：默认仅本地存储检测数据；可选匿名统计。
2. **我们如何使用**：用于色觉筛查和产品优化。
3. **我们如何共享**：不与任何第三方共享个人数据。
4. **数据存储**：本地优先，服务端仅存脱敏统计。
5. **您的权利**：查看、导出、删除数据；拒绝上报。
6. **联系**：隐私问题联系邮箱。
7. **政策变更**：重大变更会提前通知。

## 7. 安全事件响应

### 7.1 事件分级

| 级别 | 定义 | 响应时限 |
|------|------|----------|
| P0 | 大规模用户数据泄露 | 立即响应，24h 内通报 |
| P1 | 部分数据异常访问 | 4h 内响应 |
| P2 | 潜在风险但未造成影响 | 24h 内评估 |

### 7.2 响应流程

1. 确认事件影响范围。
2. 定位并修复漏洞。
3. 评估受影响数据（本项目主要为本地数据，服务器风险面小）。
4. 如涉及用户数据，依法向监管机构和个人通报。
5. 事件复盘与改进。

## 8. 开发安全规范

### 8.1 代码安全

- [ ] 不使用 `dangerouslySetInnerHTML` 渲染不可信内容。
- [ ] 不将 API Key / 密钥写入前端代码。
- [ ] 定期 `npm audit` 检查依赖漏洞。
- [ ] 代码评审关注隐私相关改动。

### 8.2 日志规范

- 服务端日志不记录请求体。
- 不记录用户 IP 和身份信息。
- 日志保留期限不超过 30 天。

### 8.3 第三方服务

引入任何第三方服务（分析、监控、SDK）前需评估：
- 是否收集用户数据？
- 数据如何存储和处理？
- 是否符合隐私政策？
- 是否可配置关闭？
