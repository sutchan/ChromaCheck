## 2. P0 任务（安全与合规）

### O-01 Next.js 安全补丁升级

- **问题背景**：`package.json` 固定 `next@14.2.15`；npm 提示该版本存在 2025-12-11 披露的安全漏洞。14.x 最新补丁为 `14.2.35`。
- **实施方案**：沿用 Next.js 14 同 minor 补丁升级，避免跨 major 破坏 App Router 行为。① 修改 `next` 与 `eslint-config-next` 为 `14.2.35`；② `npm install` 更新锁文件；③ 跑 lint / type-check / test / build；④ Vercel Preview 冒烟后合入 `main`；⑤ 按版本规则 bump 并更新 CHANGELOG。
- **预期效果**：已知 CVE 归零，`npm audit` 关键项 0，构建行为不变。
- **验收标准**：四项门禁全绿 + Preview 主流程通过 + `npm audit --omit=dev` 无 critical。
- **责任人 / 计划**：待指派（前端维护者）／2026-12-05。

### O-02 语言恢复时 `html lang` 同步

- **问题背景**：`app/layout.tsx` 初始硬编码 `lang="zh-CN"`；`LangProvider.tsx` 挂载后从 `cc.lang.v1` 恢复语言时未改写 `<html lang>`，仅主动 `setLang()` 才更新。繁中 / 英文用户首屏语义标记错误（WCAG 3.1.1）。
- **实施方案**：抽出 `applyHtmlLang(lang: Lang)` 调用 `htmlLang()` 并写入 `document.documentElement.lang`；初始化 effect 与 `setLang()` 统一调用；补组件测试分别断言 `zh-CN` / `zh-TW` / `en`。
- **预期效果**：三语 `html lang` 正确率 100%。
- **验收标准**：三种语言刷新后属性与所选语言一致，测试通过。
- **责任人 / 计划**：待指派（前端维护者）／2026-12-05。

## 3. P1 任务（质量与验证）

### V-01 OpenAPI 规范机器校验

- **背景**：`docs/openapi.yaml` 为手写 OpenAPI 3.1 规范，尚未机器校验。
- **方案**：引入 `swagger-cli` 或 `redocly-cli`，CI 增加 `validate docs/openapi.yaml`，脚本比对 Route Handler 实际路径。
- **预期效果**：规范解析错误 0，文档与代码路径漂移 0。
- **验收标准**：CI 校验步骤通过。

### V-02 文档链接与版本展示位一致性

- **背景**：本次新增 5 份文档并统一任务文档路径，需确认交叉引用与版本展示位一致。
- **方案**：脚本扫描 `docs/**/*.md` 与 README 相对链接及版本展示位，结果写入 `reports/`。
- **预期效果**：断链 0，版本漂移 0。
- **验收标准**：脚本输出 0 错误。

### O-03 覆盖率门禁与 Playwright 主链路 E2E

- **背景**：`vitest.config.ts` 无 `coverage` 块，CI 只跑 `npm test`；E2E 为跳过占位。15 文件 107 例覆盖判读逻辑，UI 关键路径无自动回归。
- **方案**：① 配置 `coverage.provider = 'v8'` 与 `thresholds`（lines 80 / functions 75 / branches 70 / statements 80），CI 增加 `npm run test:coverage`；② 引入 Playwright，覆盖「首页 → 指引 → 石原氏快速 → 结果 → 导出 PNG」。
- **预期效果**：覆盖率可量化并纳入门禁；核心链路回归从人工约 15 分钟降至自动约 2 分钟。
- **验收标准**：覆盖率报告生成且门禁通过；E2E 在 CI 稳定 3 次。
