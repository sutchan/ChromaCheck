## 1. 产品概述

### 1.1 产品定位

色辨（ChromaCheck）是一款基于 Web 的在线色觉检测工具，通过标准化的石原氏色盲检测图（Ishihara Test）及多种色觉测试范式，帮助用户快速、便捷地筛查色觉异常（红绿色盲、色弱等），并提供科学的结果解读与就医建议。

### 1.2 产品目标

- **用户目标**：让普通用户无需专业设备，在家即可完成初步色觉筛查，了解自身色觉状况。
- **业务目标**：打造国内领先的在线色觉检测平台，积累色觉数据，拓展职业体检、眼科转诊等 B 端合作场景。
- **体验目标**：检测流程简洁流畅，结果呈现直观易懂，全程不超过 3 分钟。

### 1.3 目标用户

| 用户分层 | 特征 | 核心需求 |
|----------|------|----------|
| 普通大众 | 怀疑自身色觉异常，或出于好奇 | 快速检测、易懂结果 |
| 求职/升学人群 | 需确认是否符合专业/职业色觉要求 | 权威检测、报告导出 |
| 家长 | 关注儿童色觉发育 | 适龄测试、温和界面 |
| 医疗机构/学校 | 批量筛查需求（远期） | 批量管理、数据统计 |

### 1.4 使用场景

1. **个人自查**：用户在浏览器中打开网站，按指引完成检测，获取色觉评估报告。
2. **术前/入职预筛**：用户在正式体检前自行预查，了解可能的结果。
3. **科普教育**：学校或机构用于色觉科普教学演示。

## 2. 市场与竞品分析

### 2.1 市场背景

- 全球男性色觉异常患病率约 8%，女性约 0.5%，中国患者基数庞大。
- 传统色觉检测依赖纸质石原氏图谱，受环境光、图谱磨损、判读主观性影响。
- 在线检测工具可标准化呈现、自动判读、数据可追溯，具备显著优势。

### 2.2 竞品分析

| 竞品 | 优势 | 不足 |
|------|------|------|
| 色弱测试（微信小程序） | 入口便捷 | 测试图少，结果粗糙 |
| 眼科医院在线测试 | 权威性高 | 界面老旧，流程繁琐 |
| EnChroma 在线测试 | 国际化，界面精美 | 英文为主，本土化不足 |
| 色辨 ChromaCheck（本产品） | 中文界面、标准化流程、多范式测试、报告可导出 | 品牌认知度待建立 |

### 2.3 差异化策略

1. **多范式测试**：不仅有石原氏数字图，还包含路径追踪图、色相排列测试（Farnsworth-Munsell 简化版）。
2. **科学判读算法**：基于答题模式（不仅看对错，还看错误类型）推断色觉异常类型与程度。
3. **中文本土化**：全中文界面，结果解读贴合国内职业体检标准（如《机动车驾驶证申领和使用规定》色觉要求）。
4. **隐私优先**：检测数据本地存储，不强制注册，用户可自主选择是否上传。

## 3. 功能需求

### 3.1 功能架构

```
色辨 ChromaCheck
├── 首页（Landing）
│   ├── 产品介绍
│   ├── 检测入口
│   └── 科普知识
├── 检测模块
│   ├── 检测前指引
│   ├── 石原氏数字图测试（主测试）
│   ├── 路径追踪图测试（进阶）
│   └── 色相排列测试（进阶，可选）
├── 结果模块
│   ├── 色觉评估结果
│   ├── 异常类型与程度
│   ├── 详细解读
│   ├── 职业/生活建议
│   └── 报告导出（图片/PDF）
├── 科普模块
│   ├── 色盲/色弱知识
│   ├── 常见误区
│   └── 就医指南
└── 用户中心（轻量）
    ├── 历史记录（本地存储）
    └── 设置（音效、对比度等）
```

### 3.2 核心功能详述

#### F1. 首页（Landing Page）

| 字段 | 说明 |
|------|------|
| 功能描述 | 产品门面，展示核心价值，引导用户开始检测 |
| 入口 | 用户访问根路径 `/` |
| 页面元素 | Hero 区（产品名 + Slogan + "开始检测"按钮）、检测流程三步图示、产品特点卡片、科普文章入口、页脚 |
| 交互 | 点击"开始检测"→ 跳转检测前指引页 |
| 验收标准 | 首屏加载 < 2s；CTA 按钮在首屏可见；移动端适配良好 |

#### F2. 检测前指引

| 字段 | 说明 |
|------|------|
| 功能描述 | 告知用户检测注意事项，确保检测条件符合要求 |
| 页面元素 | 环境光要求（避免强光/反光）、观看距离建议（约 50-70cm）、无需佩戴有色眼镜、检测时长说明（约 2-3 分钟）、免责声明 |
| 交互 | 用户勾选"我已了解并准备就绪"→ "开始检测"按钮激活 → 进入测试 |
| 验收标准 | 未勾选时按钮置灰不可点；免责声明文字清晰可读 |

#### F3. 石原氏数字图测试（主测试）

| 字段 | 说明 |
|------|------|
| 功能描述 | 核心检测模块，展示石原氏检测图，用户输入看到的数字 |
| 题量 | 标准版 24 题（含演示题 2 道 + 正式题 22 道）；快速版 10 题 |
| 题目类型 | 数字图（正常色觉可见数字，异常者不可见或看到不同数字）、设计图（用于区分正常与伪色盲） |
| 页面元素 | 检测图（居中，最大尺寸限制）、题目进度指示器、输入框（数字键盘或手动输入）、"看不清/无数字"选项、上一题/下一题按钮 |
| 交互规则 | 1. 每题无时间限制，但记录答题时长（过长可能提示异常）；2. 允许返回修改；3. 输入后自动进入下一题（可配置）；4. 演示题提供正确答案反馈，正式题不反馈 |
| 数据记录 | 每题：题目 ID、用户答案、正确答案、是否正确、答题时长、是否选择"看不清" |
| 验收标准 | 图片加载无闪烁；输入支持键盘回车提交；进度条实时更新；移动端数字键盘友好 |

#### F4. 路径追踪图测试（进阶，v1.1+ 实现，见 SPEC §1.2）

| 字段 | 说明 |
|------|------|
| 功能描述 | 用户用鼠标/手指在图中追踪可见的色点路径，用于区分红/绿色盲类型 |
| 题量 | 3-5 题 |
| 页面元素 | 路径图（Canvas 渲染）、画笔工具、清除按钮、提交按钮 |
| 交互 | 用户在图上描绘路径，系统比对路径与标准答案的重合度 |
| 验收标准 | 支持鼠标和触摸操作；轨迹平滑无明显卡顿；清除后可重画 |

#### F5. 色相排列测试（进阶，v1.1+ 实现，见 SPEC §1.2）

| 字段 | 说明 |
|------|------|
| 功能描述 | 用户按色相顺序排列色卡，检测色觉辨别精度（简化版 Farnsworth-Munsell D15） |
| 题量 | 1 组（15 张色卡 + 1 张固定首尾卡） |
| 页面元素 | 色卡列表（可拖拽排序）、参考首尾色卡、提交按钮 |
| 交互 | 拖拽/点击交换色卡位置；提交后计算总误差分数（TES） |
| 验收标准 | 拖拽流畅；色卡颜色准确（sRGB 色域）；支持移动端点击排序 |

#### F6. 结果评估与展示

| 字段 | 说明 |
|------|------|
| 功能描述 | 根据答题数据计算色觉评估结果，分维度展示 |
| 评估维度 | 1. 总体结论（正常 / 疑似色弱 / 疑似色盲 / 需进一步检查）；2. 异常类型（红色盲/红色弱/绿色盲/绿色弱/蓝色盲/全色盲）；3. 异常程度（轻度/中度/重度）；4. 置信度（基于答题一致性） |
| 判读算法 | 基于石原氏标准判读规则：特定题目组合对应特定色觉类型；结合错误模式、答题时长、路径追踪重合度综合评分 |
| 页面元素 | 结果总览卡片（结论 + 类型 + 程度）、各维度得分雷达图/条形图、答题明细（可展开）、详细解读文本、生活/职业建议、"重新检测"按钮、"导出报告"按钮 |
| 验收标准 | 结果在检测完成后 < 1s 呈现；图表渲染正确；解读文字无医学诊断用语（使用"疑似""建议就医"等措辞） |

#### F7. 报告导出

| 字段 | 说明 |
|------|------|
| 功能描述 | 将检测结果导出为图片或 PDF，便于保存和分享 |
| 导出格式 | PNG 图片（适合社交媒体分享）、PDF（适合打印/存档） |
| 报告内容 | 产品 Logo、检测日期、用户编号（匿名）、各项结果、答题摘要、免责声明 |
| 验收标准 | 导出文件可正常打开；内容排版整齐；中文字体正确渲染；文件大小合理（< 5MB） |

#### F8. 科普模块

| 字段 | 说明 |
|------|------|
| 功能描述 | 提供色觉相关科普知识，提升用户认知，增加页面停留 |
| 内容分类 | 色盲/色弱是什么、遗传规律、常见误区、生活小贴士、职业限制说明、就医指南 |
| 呈现形式 | 图文文章列表 + 详情页 |
| 验收标准 | 文章内容准确（经医学顾问审核）；排版适合阅读；支持分享 |

#### F9. 历史记录（本地存储）

| 字段 | 说明 |
|------|------|
| 功能描述 | 在用户本地浏览器保存检测历史，无需注册 |
| 存储方式 | localStorage（加密存储基本结果，不存储原始答题数据） |
| 功能 | 查看历史结果列表、对比历次结果、删除单条记录、清空全部 |
| 隐私 | 明确告知数据仅存于本地；提供一键清除 |
| 验收标准 | 关闭浏览器后数据不丢失；清除后不可恢复；存储容量不超过 1MB |

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 首屏加载时间 | < 2s（4G 网络） |
| 检测图加载时间 | < 500ms（预加载下一题） |
| 结果计算时间 | < 500ms |
| 页面切换动画 | < 300ms，流畅无卡顿 |
| 部署形态 | 纯前端静态托管，可水平扩展（无服务端状态，不承诺服务端并发能力） |

### 4.2 兼容性需求

| 维度 | 要求 |
|------|------|
| 浏览器 | Chrome 90+、Safari 15+、Firefox 90+、Edge 90+ |
| 设备 | 桌面端（1920×1080 及以上）、平板（iPad 等）、手机（375×667 及以上） |
| 操作系统 | Windows 10+、macOS 12+、iOS 15+、Android 10+ |
| 屏幕 | 支持 Retina/高 DPI 屏幕；色准要求 sRGB 色域 |

### 4.3 可用性需求

- 检测流程不超过 3 步进入正题，总时长不超过 3 分钟。
- 所有交互元素有明确的状态反馈（hover/active/disabled）。
- 错误提示友好，不使用技术术语。
- 支持键盘导航（Tab 键切换，Enter 确认）。
- 字体大小不小于 14px，正文行高 1.6。

### 4.4 隐私与安全

- **数据最小化**：不强制收集个人信息，检测数据默认本地存储。
- **匿名化**：如用户选择上传数据，仅上传脱敏后的统计数据，不含个人标识。
- **HTTPS**：全站强制 HTTPS。
- **免责声明**：明确说明本工具仅为筛查参考，不能替代专业医学诊断。
- **合规**：遵循《个人信息保护法》《数据安全法》，不将用户数据用于未经授权的用途。

### 4.5 可维护性

- 代码遵循 ESLint + Prettier 规范。
- 组件粒度合理，单一职责。
- 测试数据与业务逻辑分离，便于后续扩充题库。
- 判读算法独立模块，支持版本迭代和 A/B 测试。

## 5. 用户流程

### 5.1 主流程（快速检测）

```
用户访问首页
    ↓
点击"开始检测"
    ↓
检测前指引页 → 勾选确认 → 开始
    ↓
石原氏数字图测试（10题/快速版 或 24题/标准版）
    ↓
提交答案
    ↓
结果计算（< 1s）
    ↓
结果展示页
    ↓
[可选] 进阶测试（路径追踪 / 色相排列）
    ↓
[可选] 导出报告
    ↓
[可选] 查看科普 / 重新检测
```

### 5.2 异常流程

| 异常场景 | 处理方式 |
|----------|----------|
| 用户中途退出 | 自动保存进度到本地，下次访问提示"继续上次检测" |
| 图片加载失败 | 显示占位图 + 重试按钮；连续失败 3 次提示检查网络 |
| 用户答题过快（< 1s/题） | 不拦截，但在结果中降低置信度，提示"答题过快可能影响准确性" |
| 结果无法判定（答题矛盾） | 显示"检测结果不确定，建议重新检测或就医"，不强行给出结论 |

## 6. 数据需求

### 6.1 检测题库数据结构

> 字段名与枚举以 [docs/SPEC.md §5.1](docs/SPEC.md) 为权威（原型 `prototype/assets/js/data.js` 实证）。

```typescript
interface IshiharaQuestion {
  id: string;                    // 题目唯一标识
  plate: number;                 // 石原氏图版号
  type: 'demonstration' | 'normal' | 'transformation' | 'vanishing' | 'hidden' | 'classification'; // 6 值枚举
  answer: string;                // 正常色觉答案（数字）；hidden 题为 ''
  protan?: string;               // 红色觉异常典型误读
  deutan?: string;               // 绿色觉异常典型误读
  answerTritan?: string;         // 蓝色觉异常典型误读（v1.0 暂未启用）
  difficulty: 1 | 2 | 3;
  quick: boolean;                // 是否纳入快速版
}
```

### 6.2 检测结果数据结构

> 字段以 [docs/SPEC.md §5.3](docs/SPEC.md) 为权威（TestResult 内聚 `ishihara` 评分对象，含 `correctCount`）。

```typescript
interface TestResult {
  id: string;
  userId: string | null;          // 匿名用户为 null
  testMode: 'quick' | 'standard' | 'advanced';
  startTime: string;              // ISO 时间
  endTime: string;
  ishihara: IshiharaScoringResult; // 含 overall/type/severity/confidence/dimensions，定义见 SPEC §5.3
  advancedResults?: {
    pathTracking?: PathTrackingResult;
    hueArrangement?: HueArrangementResult;
  };
}
```

## 9. 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 屏幕色彩差异导致检测不准 | 高 | 高 | 提供屏幕校准指引；结果中注明"结果受屏幕显示影响"；使用标准化 sRGB 图片 |
