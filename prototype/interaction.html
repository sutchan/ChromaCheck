模式 Patterns

跨页面复用的结构性交互方式。每个模式都定义「何时用、怎么用、不要怎么用」。

导航与路由

检测流程用线性分步（引导 → 逐题 → 结果）。同层视图用标签切换；跨页跳转保留「返回」。当前步骤高亮且带有文字/序号，不只靠颜色。

输入模式（数字键盘）

答案输入用自定义数字键盘而非系统键盘，避免移动端遮挡；支持物理键盘 0-9、Enter 提交、← 退格。答案回显带光标态。

—

选择模式（单选芯片）

互斥选项用芯片（chip）单选，选中态用填充 + 对勾双编码；键盘可用方向键在组内移动，并暴露 aria-checked。

加载占位

内容未就绪用骨架屏（shimmer），比转圈更可预期；>400ms 才显示，避免闪烁。骨架结构须贴近真实布局。

反馈 Feedback

用户每次操作都应在 100ms 内获得可见反馈；结果性反馈带语义色与图标，并进入 aria-live 区域。

Toast 提示

轻量、自动消失（4s）、不阻断。四类：成功/信息/警告/错误，分别配色 + 图标 + 文案。批量同类只展示一条。

进度与完成

多步任务显示进度（题号 / 百分比）；完成态用对勾 + 文字收尾，不依赖颜色判断成败。

错误 Errors

错误用「问题 + 原因 + 怎么做」三段式；禁止只有红字。阻断式错误提供重试入口，且可 Esc 关闭。

表单内联错误

字段级错误就近展示，关联 aria-describedby；错误图标 + 文字，输入聚焦时自动滚动到首个错误。

阻断式错误（模态）

影响整条任务的错误用模态呈现，含标题、说明、主操作（重试/关闭）；焦点被困在模态内，Esc 关闭。

上传失败

网络中断导致报告未能保存，可重试或稍后从本地草稿恢复。

无结果 / 网络错误

列表为空或请求失败，给出状态卡 + 原因 + 可操作按钮（重试/返回），不显示空白崩溃页。

无法连接服务器

请检查网络后重试；本地草稿仍可查看。

空状态 Empty States

空不是「无内容」，而是引导下一步的机会：图标 + 一句说明 + 一个主行动，必要时给次要操作。
