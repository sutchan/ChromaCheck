2026-11-05 对 ChromaCheck 全仓做审查与修复，沉淀以下非显然要点（避免后续会话重蹈）：

**1. JSON-LD 注入已做 `</script>` 转义**
`components/seo/JsonLd.tsx` 的 `safeJson()` 将 `<` `>` `&` 与行/段分隔符（`\u2028`/`\u2029`）转义为 `\u003c` 等，纵深防御脚本断点注入。即便数据来自可信常量也保持该转义——勿移除。

**2. 语义 id 覆盖状态**
- 全部 `app/*` 页面与绝大多数 `components/*` 关键容器均已带 kebab-case 语义 id（如 `main-content`/`result-page`/`guide-page`/`app-footer`）。
- 本次为 `guide`/`learn`/`privacy`/`offline` 四个服务端壳页面补了根容器 id（`guide-page` 等）。
- 原型 `prototype/*.html` 已有 47+ 语义 id，且 `prototype/assets/js/*.js` 超 200 行文件**豁免拆分**（设计参考、经典全局脚本，详见 `prototype_reference_exempt.md`）。

**3. SPEC §6.3 判读阈值 = wrongRate 比例，非绝对计数**
实际实现（`lib/scoring.ts`）用 `wrongRate = wrong/total`：`suspected_blindness` 阈值 `0.6`、`suspected_deficiency` 阈值 `0.3`、`inconclusive` 需 `wrongRate < 0.3`。SPEC §6.3 早先写的是绝对计数（`wrong>=8`/`wrong>=4`），已修订对齐代码与 97 例单元测试。后续若动 `scoring.ts` 判读阈值，**必须以比例口径、并同步改测试**。

**4. 测试环境限制**
Vitest 跑在 node 环境（`vitest.setup.ts` 注入内存 Storage，无 jsdom/happy-dom），故 `report-canvas.ts`(`drawReport`)/`sharecard-canvas.ts`(`drawShareCard`) 的 Canvas 绘制不可单测（仅 `sharecard.ts` 的 `computeRadar` 有覆盖）。勿强行加 jsdom。

**5. 版本与构建**
- 版本单一来源 `VERSION`=`package.json`=`1.13.2`（2026-11-05）；CHANGELOG 顶部与 `[1.13.2]` 节已存在，新增改动**追加**到该节、勿建重复节。
- `next build` 在本地可能被腾讯 coding-copilot 的 safe-delete shim 拦截（ETIMEDOUT）；CI 不提交 lock 文件，`ci.yml` 勿配 `cache: npm`，用 `npm install`。
- 页脚 `components/layout/Footer.tsx`(`id="app-footer"`) 展示 `© · v{ver} · build {NEXT_PUBLIC_BUILD_ID} · {用途}`，版本号直读 `package.json`；`lib/site.ts` 的 `SITE_UPDATED` 现仅用于隐私页「最后更新」。
